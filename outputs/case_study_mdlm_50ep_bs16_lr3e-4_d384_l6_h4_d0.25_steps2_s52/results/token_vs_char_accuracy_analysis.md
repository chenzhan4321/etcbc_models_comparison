# Token级 vs 字符级准确率分析报告

## 核心问题

**Token级准确率**: 97.05%
**字符级准确率（Levenshtein）**: 96.48%
**差距**: 0.57个百分点

用户疑问：为什么字符级准确率会比token级低这么多？

## 数据验证

### Token级统计
- 总tokens: 404,962
- 正确tokens: 393,029 (97.05%)
- **错误tokens: 11,933**

### 字符级统计
- 总字符数: 608,769
- Levenshtein编辑距离: 21,420
- 字符级准确率: 96.48%

### Token到字符的映射
- **平均每token对应: 1.50字符**
- Pattern长度范围: 0-11字符
- 平均pattern长度: 4.20字符（但包含空格等分隔符）

## 错误传播分析

### 理论预期 vs 实际

如果简单假设1个错误token = 1.50个错误字符：
```
理论字符错误数 = 11,933 × 1.50 = 17,939
理论字符准确率 = 1 - 17,939/608,769 = 97.05%
```

但**实际情况**：
```
实际字符错误数（Levenshtein距离）= 21,420
实际字符准确率 = 96.48%
```

### 放大系数

**实际放大系数 = 21,420 / 11,933 = 1.80**

这意味着平均每个错误token导致**1.80个字符的编辑距离**，而不是预期的1.50。

## 为什么放大系数 > 1.50？

### 1. Levenshtein距离的特性

Levenshtein距离不是简单的字符替换计数，而是包含三种操作：
- **插入**（Insertion）
- **删除**（Deletion）
- **替换**（Substitution）

当错误token还原后的长度与正确token不同时，会产生额外的插入/删除操作。

### 2. 实际观察

在前100个有错误的行中：
- **40%的行存在长度差异**
- 平均长度差异：**2.70字符**

示例（实际错误样本）：
```
错误1: 1个token错误 → 10个字符编辑距离
  Pred: W-TWBL[-K
  Gold: W-!T=!](>](J&WBL[-K
  差异: 预测缺少了"!T=!](>](J&W"部分

错误2: 1个token错误 → 7个字符编辑距离
  Pred: >S(>=/(J~>/
  Gold: >S>/ <M
  差异: 长度完全不同
```

### 3. 长pattern的影响

最长的patterns：
- Tag 268: `==[/(>-(>(N` (11字符)
- Tag 190: `!(>(T@(>&` (9字符)
- Tag 329: `<UNKNOWN>` (9字符)

当这些长pattern对应的token预测错误时，会导致大量字符错误。

## 还原管道验证

**重要验证**：检查token完全正确的行，在original层面是否有字符错误？

结果：✅ **0行**

这证明：
- 还原管道**没有引入额外错误**
- 所有字符级错误都来自token级错误
- 还原过程是**确定性和正确的**

## 结论

### Token级准确率97.05% → 字符级准确率96.48%是合理的

原因：

1. **放大效应**:
   - 平均每token 1.50字符
   - Levenshtein放大系数 1.80
   - 差异来自插入/删除操作

2. **长pattern影响**:
   - 某些token对应11字符pattern
   - 这些token错误导致大量字符错误

3. **长度不匹配**:
   - 40%的错误行存在长度差异
   - 平均差2.70字符
   - 长度差异导致额外的编辑距离

### 数学验证

```
Token错误: 11,933
实际字符错误（Levenshtein）: 21,420
字符准确率: 1 - 21,420/608,769 = 96.48% ✓
```

### 是否合理？

**是的，这是合理的**，因为：

1. Levenshtein距离≠简单字符替换数
2. 不同长度的token对字符级影响不同
3. 错误token的还原结果长度可能不同

### 对比其他评估方式

| 评估方式 | 准确率 | 说明 |
|---------|--------|------|
| Token级（数字序列） | 97.05% | 每个数字token的准确率 |
| 字符级（Levenshtein） | 96.48% | 还原文本的编辑距离 |
| 序列级（完美匹配） | 45.01% | 整行完全正确的比例 |

## 如果想提高字符级准确率？

需要关注：
1. **长pattern对应的token**（如tag 268, 190等）
2. **高放大系数的错误**（比例>3的有239个样本）
3. **导致长度变化的错误**（40%的错误行）

优化这些高影响的错误类型，可以显著提高字符级准确率。
